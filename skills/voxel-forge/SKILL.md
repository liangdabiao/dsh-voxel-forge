# 3D 形体 → 逐层切片 → 积木

把 3D 模型（GLB）**真的按层切开**：几何与颜色唯一来源 = 模型文件本身（顶点 + 法线 + UV + baseColor 贴图）。
这是"形体优先"的做法：件数不设上限，外形、空腔、朝向必须忠实于原作。

两条路线，按手上有什么选：

- **有模型文件**（用户面板上传，或给本机路径 → `action="upload"`）→ 切片路线。写实照片取色 / 凭渲染图想象形状这两条路**都被否决过**（形状失真 + 颜色全错），不要走。
- **只有体素风/像素风参考图**（块面清楚、色块分明）→ 程序化路线：面板上传图片（或 `action="upload", path=<图片绝对路径>`）会存成 `ref/ref.<ext>`，然后 `action="read", what="ref"` 拿路径 → **`read_image` 亲眼看图** → `action="scene"` 写场景 → `action="gen"` 生成。图里的块面就是格子决策，照块面写基本形最准。
- 上传入口按扩展名自动分流：`.glb/.gltf` 走切片，`.jpg/.jpeg/.png/.webp` 走参考图；写实照片先跟用户对齐预期（取色会形状失真 + 颜色全错）。

## 铁律（违反必然返工）

1. **不要从图片取色**——颜色只来自模型贴图。
2. **不要按列 min..max 填实**——那是"竖直柱子"的根因。切片管线已内置三维洪泛判内外，装配层不做修补。
3. **装配不做智能修补**（不补柱/不改色/不剪格子）——几何与颜色的所有决策在切片参数里完成。
4. **先用球验证链路**（`action="ball"`）：24 层每层一色的球。球错了停下修管线。
5. **分辨率按原作尺寸给**：0.9 m 坐像 96 层；**五官要分开得上 128 层**；96 层五官会糊。
6. **改一个假设、验一次**：几何错和颜色错分开修；修完必须凑近看（probe ASCII / 验收图），不靠"参数开了就该好"。

## 工作流

### 1. 拿到模型

- 用户面板上传（GLB 上传即 64 层快速切片出验收图；图片上传则存为参考图）或 `voxel_forge(action="upload", name=模型名, path=本机GLB或图片绝对路径)`
- 模型格式 `.glb`/`.gltf`（需要顶点/法线/UV/baseColorTexture 四件套；WebP 贴图不支持，先转 PNG）
- 图片格式 `.jpg`/`.jpeg`/`.png`/`.webp`：导入后必须先 `action="read", what="ref"` 拿绝对路径并 `read_image` 看图，再决定体素风与否

### 2. 切片

`voxel_forge(action="slice", name=..., courses=...)`

| 参数 | 默认 | 说明 |
|---|---|---|
| courses | 96 | 人像 128；小物件 64~96 |
| merge | default | 内置材质归并表；none 看原始贴图 |
| absorb | 3 | ≤N 格孤立色块并入邻域主色；4~6 治脏，太大会吃细节 |
| denoise | 2 | 3×3×3 去噪轮数；0=关（查细线丢失用——会吃 1 格宽细线） |
| darkdetail | 0.32 | 细黑线保底（闭眼/嘴缝/刻线：黑覆盖占比达标就取黑） |

### 3. 验收（省不得）

切片完成即出验收图（面板可见；`action="preview"` 重出）。**判读标准**：

- 正视图轮廓与模型一致，**不是**一根根竖直柱子；
- 抬手臂/裙摆下方是空的（悬垂空腔保住了）；
- 颜色分区合理，无大面积斑驳噪点；
- **脸要凑近单独看**：眉/眼/胡子三层分开，眼睛不能消失。

数据化排查：`action="probe"`（stats 颜色分布 / layers+cols 正面 ASCII / profile 深度剖面）。深度剖面最关键：目标色 z=42 但 z=44 还有格子 = 可见面被回填盖住（几何问题不是颜色问题）。

### 4. 装配

`voxel_forge(action="build", name=...)` → out/（set.html 3D、model.ldr、parts.csv BOM、report.txt、check.json）+ 版本快照。

- **已知未解决（如实告知用户）**：voxel 模型通常有大量 `not connected`（底部悬空/异色同层不连接/悬挑）——体素塑像的特性，可拼搭性检查按报告如实汇报即可，不要为了 0 错误去"补柱子"（会把空腔焊死）。
- 细黑线/眼睛在 128 层仍可能不出：`--denoise 0` 对照、probe profile 查是不是被埋——若两处都开了仍没有，**如实说明**，不要照抄结论。

### 5. 缩放

用户说"小一半" = 层数减半。**用 `action="downscale"` 归并，不要降 courses 重切**（重切全量采样慢且内存峰值大；归并 2 秒、确定性）。代价必说：1 格宽细结构（鹿角尖/手指/衣带）会变粗或断开。

### 6. 程序化路线（参考图本身是体素风时）

`action="scene"` 存场景（JS 模块 `export function build(v)`）→ `action="gen"` 生成 → 同样验收/装配。

进这条路之前必须先看图：`action="read", what="ref"` 拿参考图绝对路径 → `read_image` 亲眼看。判断标准是块面是否清楚（哪里 1 格、哪里 3 格）；写实照片不要硬做，先跟用户对齐"换 GLB 模型"或"我按大致块面抽象一版，件数会很多"。

| 形体 | 方法 |
|---|---|
| 主体体积 | `v.ellipsoid(cx,cy,cz,rx,ry,rz,色)` |
| 浮岛/树干/塔身 | `v.revolve(cx,cz,radii,top_y,色回调)`，radii 由上往下 |
| 尾巴/四肢/斜向体 | `v.tube(path,radius,色)`，radius=0 逐格线（**斜向体至少 3 格粗**，1 格厚渲染会断） |
| 方块/眼睛 | `v.box(...)` / `v.put(x,y,z,色)` |
| 换色不改几何 | `v.repaint(pred,色,only=['旧色'])` |
| 草皮/岩层杂色 | `v.hash01(x,y,z,salt)` 阈值分流（确定性，可复现） |

三条实测教训：①形体问题必须看 3D 渲染图（正视图会骗人）；②附件按主视角放（放主体侧面会被挡掉）；③示例见 examples/island.mjs（鲸鱼浮岛，913 格 → 164 件）。

## 错误处理

| 情况 | 处理 |
|---|---|
| GLB 缺 NORMAL/UV/贴图 | 如实说明该模型切片需要四件套，建议换模型或先补导出 |
| 贴图 WebP | 让用户转 PNG 再上传 |
| 几乎全白 | 取色退化（历史 bug 已修），报给用户并建议换模型验证 |
| build 大量 not connected | 如实汇报（体素塑像特性），禁止补柱子 |

## 注意事项

- 数值全部来自管线输出，**严禁估算或编造**
- 分类朝向自动判断（up = 最大包围盒轴）；朝向不对让用户在源模型里转好再传
- 上游 references/（pipeline/pitfalls/procedural/validation）是完整算法与复盘，深挖时读

## 在 DSH 插件里使用

- `voxel_forge` 管切片/生成/装配/体检/缩放；面板管上传（入口）/验收图/3D 对照/BOM/时间线
- 面板上传即 64 层快速切片（先看效果），细节档让 agent `slice courses=128`
- `history`/版本对比在面板时间线；交付物直接从模型页下载
